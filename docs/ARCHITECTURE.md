# Архитектура решения C

## Классификационный тракт

Модель получает категорию, название и описание товара в одном chat prompt.
Цель обучения — следующий токен `да` для label 1 и `нет` для label 0. Во время
инференса генерация не запускается:

```text
p_yes = softmax([logit("да"), logit("нет")])[0]
```

Описание сокращается до тех пор, пока полный prompt не помещается в 1024
токена. Название и вопрос сохраняются.

## Five-fold LoRA soup

Для каждого fold-ингредиента `i` LoRA-delta равен
`(alpha / rank) * B_i @ A_i`. Средний delta пяти адаптеров представляется одним:

```text
A_cat = concat(A_1, ..., A_5, axis=0)
B_cat = concat(B_1, ..., B_5, axis=1) / 5
```

Поэтому `B_cat @ A_cat = mean(B_i @ A_i)`. `rank` и `alpha` одновременно
умножаются на пять; коэффициент `alpha/rank` остаётся равен двум. Получается
rank 80 / alpha 160 и один forward вместо пяти. Математика проверяется тестом
`tests/test_make_soup.py`.

## Решение и fail-safe

Порог выбирается отдельно для каждой категории. После порога применяется один
узкий отрицательный override для empirically stable варианта «вечной спички».
Renderer комментария вызывается после этого и не возвращает новую метку.

До загрузки модели `run.py` записывает полный CSV с category-default метками.
После полного скоринга файл заменяется результатом модели. Это защищает формат
при runtime-ошибке, но fallback не считается полноценным инференсом.
