# Архитектура решения A

## Классификационный тракт

Модель получает категорию, название и описание товара в одном chat prompt.
Цель обучения — следующий токен `да` для label 1 и `нет` для label 0. Во время
инференса генерация не запускается: scorer читает только два logits и вычисляет

```text
p_yes = softmax([logit("да"), logit("нет")])[0]
```

Описание сокращается до тех пор, пока полный prompt не помещается в 1024
токена. Название и вопрос сохраняются; простое отбрасывание начала sequence не
используется.

## LoRA soup

Для каждого ингредиента `i` LoRA-delta равен
`(alpha / rank) * B_i @ A_i`. Средний delta шести адаптеров представляется
одним адаптером:

```text
A_cat = concat(A_1, ..., A_6, axis=0)
B_cat = concat(B_1, ..., B_6, axis=1) / 6
```

Тогда `B_cat @ A_cat = mean(B_i @ A_i)`. `rank` и `alpha` одновременно
умножаются на шесть, поэтому коэффициент `alpha/rank` остаётся равен двум.
Тест `tests/test_make_soup.py` проверяет это равенство численно и проверяет
отказ при несовместимых адаптерах.

## Решение и fail-safe

Порог выбирается отдельно для каждой категории. После порога применяется один
узкий отрицательный override для empirically stable варианта «вечной спички».
Renderer комментария вызывается после этого и не возвращает новую метку.

До загрузки модели `run.py` записывает полный CSV с category-default метками.
После полного скоринга файл атомарно заменяется результатом модели. Это
защищает формат при ошибке runtime, но fallback не считается полноценным
инференсом и должен быть виден в логах.
